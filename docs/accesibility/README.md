Welcome to the accessibility documentation for this project.

This documentation provides guidance for building accessible Android applications using **Jetpack Compose** while following **Android Accessibility Guidelines** and the **Web Content Accessibility Guidelines (WCAG)**.

# 🌍 Accessibility Standards

This project follows guidance from:

- Android Accessibility Guidelines
- Material Design Accessibility
- Web Content Accessibility Guidelines (**WCAG**) 2.2 Level AA

The four WCAG principles are:

- **Perceivable** – Users must be able to perceive information presented by the application.
- **Operable** – Users must be able to interact with and navigate the application.
- **Understandable** – Content and interactions should be clear, predictable, and easy to understand.
- **Robust** – The application should work reliably with assistive technologies such as TalkBack.

# 🧪 Accessibility Testing

Accessibility should be verified throughout development using:

- TalkBack
- Accessibility Scanner
- Large Font Sizes (up to 200%)
- Dark Mode
- Landscape Orientation
- Keyboard Navigation (where applicable)
- Voice Access (where applicable)
- Switch Access (where applicable)

# 🤝 Development Workflow

Accessibility is part of our Definition of Done.

Before a feature is merged:

- Review the Accessibility Standards.
- Complete the Accessibility Checklist.
- Test using TalkBack and Accessibility Scanner.
- Verify compliance with WCAG principles.

Accessibility is a shared responsibility across the entire development team.

---

# 💡 Accessibility Mindset

Accessibility is not a feature—it is a fundamental aspect of quality software.

When building a new feature, always ask:

- Can a blind user complete this task?
- Can someone using TalkBack understand every action?
- Can someone with low vision comfortably use this screen?
- Can someone with limited dexterity interact with every control?
- Does this feature remain usable with larger font sizes?
- Does this implementation align with WCAG principles?

If the answer is **yes**, you're building a better experience for everyone.
